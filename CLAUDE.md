## Принятые решения
- Интерфейс v3 встраивается в WPF через WebView2. C#-сервисы остаются как есть.
- Tailwind CSS не вводим, пока чиним v3 на обычном CSS с токенами. На этапе интеграции: Vite + Tailwind v4 (токены в `@theme`), стекло — отдельными классами компонентов.
- Позже такой же стиль нужен в меню внутри игры (Fabric, Java): переносится дизайн-система, а не HTML.

## Концепция дизайна: «живое окно в мир»
- Главное на экране — мир игры, интерфейс парит поверх. Никаких дашбордов из карточек.
- Одно главное действие на экран, второстепенное убрано к краям.
- Стекло подстраивается под фон: темнеет над светлым, светлеет над тёмным, текст всегда читается.
- Кнопка «Играть» превращается в прогресс, а затем в капсулу «В игре».
- Переходы между экранами — через View Transitions, анимации на spring-кривых.
- Фон и акцент меняются по реальному времени суток. Фирменный янтарный цвет — запасной.
- Шрифт Onest, крупная типографика, минимум бейджей.
- Навигация — плавающий док с «линзой» активного пункта, палитра команд по Ctrl+K.

## Производительность
- Статичный фон размывается заранее. Живой `backdrop-filter` — 0–1 слой, только в режиме full.
- Анимации только через `transform` и `opacity`. Частицы на паузе, когда окно свёрнуто.
- Режимы эффектов full / low / off. Шрифты в woff2, картинки в WebP.

## Автоматический рабочий цикл (без команд)
- Пользователь просит промт или ТЗ для Antigravity → сразу работать по скиллу `spec`.
- Пользователь присылает отчёт Antigravity или пишет «готово» → сразу работать по скиллу `verify-diff`. Если ПРИНЯТО — тут же предложить промт на следующий шаг плана.
- Отчётам агента не доверять: сверять с `git diff` и проверять глазами.
- C#: `dotnet build`. HTML: открыть страницу и проверить консоль.
