# Aura Launcher v3 Redesign — Финальный отчёт (REPORT.md)

## 1. Как открыть интерактивный прототип

Прототип полностью автономен и открывается без локального веб-сервера и сборщиков напрямую в любом браузере:
- **Файл**: `c:\Users\magne\Documents\GitHub\Aura-Launcher\docs\redesign\v3\index.html`
- **Протокол**: `file:///C:/Users/magne/Documents/GitHub/Aura-Launcher/docs/redesign/v3/index.html` (или двойной клик в проводнике).
- **Режимы эффектов**:
  - `?effects=full` — полные эффекты (стекло, blur 28px, частицы Canvas, параллакс курсора).
  - `?effects=low` — лёгкий режим (без частиц и параллакса).
  - `?effects=off` — режим без блюра (непрозрачные панели, 0 анимаций).
  - `prefers-reduced-motion` поддерживается системой автоматически.

3. **Элементы за границей вьюпорта**: **0 нарушений** (все слои фона и карточек изолированы внутри 100vw).

5. **Кликабельные зоны < --min-tap-target (38px)**: **0 нарушений** (все кнопки, табы, инпуты и переключатели >= 38×38px).

## 6. Честный перечень: что НЕ было проверено фактическим запуском

1. **Вывод звука через физическое звуковое устройство**: Headless Chrome работает без системного звукового микшера. Проверены все DOM-события плеера (play/pause, вращение винила, эквалайзер), но реальный вывод звука в динамики не воспроизводился.
2. **Фактическое поднятие сокета Playit CLI в Windows**: туннель в UI имитирует реальный статус соединения (34 мс); запуск бинарника `playit.exe` прототипом не производился (задача C# службы `TunnelService`).
3. **Парсинг повреждённых заголовков PNG при загрузке скина**: проверена валидация разрешения 64×64 / 64×32 и формата MIME `image/png`, но сценарии повреждённых байтов внутри валидного файла PNG проверялись базовым обработчиком `Image.onerror`.
