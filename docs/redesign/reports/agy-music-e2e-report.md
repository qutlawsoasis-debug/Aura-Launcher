# Отчёт: E2E-верификация Aura Music и оптимизация быстродействия

## 1. Сводка задачи
- Полная сквозная (End-to-End) верификация воспроизведения Aura Music с реальным продакшен-бэкендом `https://lobby-api.vercel.app/api/music/resolve` (без флагов `?mockyt=1`).
- Тестирование подборки из 10 разноплановых треков (русские и зарубежные, современные и классика, рок, поп, рэп).
- Проверка синхронизации текста песен (LRCLIB -> CEF `op: lyric` -> `FloatingLyrics`).
- Проверка элементов управления (пауза, продолжение, перемотка, громкость, следующий трек, воспроизведение альбома).
- Проверка обработки ошибок встраивания (коды 101/150, 404).
- Устранение лага и черного экрана при первом открытии плеера по клавише `M` (предзагрузка, рукопожатие `player_ready`, расчет анимации по системному времени `System.nanoTime()`).

## 3. Синхронизация текста песен (Lyrics Sync)

1. Загрузка текста происходит автоматически через LRCLIB API при старте трека.
2. Синхронизация выполняется по текущему таймкоду плеера (`ytPlayer.getCurrentTime()`).
3. При смене строки на странице отправляется событие CEF:
   `window.cefQuery({ request: JSON.stringify({ op: 'lyric', text: currentLine, next: nextLine, time: currentTime, duration: duration }) })`
4. В Java `HtmlBridge` парсит событие и передает в `FloatingLyrics.getInstance().onLyric(...)`, обеспечивая отображение караоке-текста над головой игрока и в HUD.
5. Интерактивность: клик по любой строке текста в плеере корректно выполняет переход (`ytPlayer.seekTo(lineTime, true)`).

---

## 4. Элементы управления и воспроизведение альбомов

- **Pause / Resume**: проверено переключение состояний через `ytPlayer.pauseVideo()` и `ytPlayer.playVideo()`. Статус плеера синхронизируется в UI.
- **Seek**: проверена перемотка на 45 сек вперед, воспроизведение продолжается с заданной секунды.
- **Volume**: изменение ползунка громкости передает значение в `ytPlayer.setVolume()` (0.5 в UI -> 50% в плеере).
- **Next Track / Queue**: по окончании воспроизведения трека (событие `YT.PlayerState.ENDED`) плеер автоматически переходит к следующему треку очереди/альбома.
- **Альбомы**: проверено открытие альбома целиком с последовательным воспроизведением треков.

## 5. Обработка ошибок воспроизведения

- Перехват кодов ошибок IFrame API:
  - `101` / `150` (воспроизведение запрещено правообладателем во встроенном плеере): отображается тост-уведомление с сообщением об ограничении и автоматическим переходом к следующей композиции.
  - Ошибки резолва (404/500): плеер откатывается на аудиопоток превью (если доступен), предотвращая зависание интерфейса.

## 6. Оптимизация открытия и устранение лага (Anti-Lag Architecture)

1. **Фоновая предзагрузка CEF**:
   - `PlayerService.schedulePreload()` запускается через 3.5 секунды после подключения к миру (или при первом вызове), создавая скрытый CEF-браузер в фоне.
2. **Двухэтапное рукопожатие готовности**:
   - Страница `player.html` после `document.fonts.ready` ожидает два кадра анимации (`requestAnimationFrame`), гарантируя завершение отрисовки CSS и разметки.
   - Отправляется событие `cefQuery({ op: 'player_ready' })`.
   - В Java `HtmlBridge` переключает флаг `ready = true` в `PlayerService`.
3. **Плавное появление экрана (`PlayerScreen.java`)**:
   - До получения `player_ready` экран отображает только размытый фон (`Blur.render()`), предотвращая мелькание черной текстуры браузера.
   - Анимация раскрытия из центра (`scale` 0.88 -> 1.0, `alpha` 0.0 -> 1.0) рассчитывается строго по системному времени `System.nanoTime()` (длительность 240 мс), полностью исключая зависимость от частоты кадров CEF.
   - Добавлено профилирование времени раскрытия: `[aura-ui PROFILING] PlayerScreen opened in {} ms`.
