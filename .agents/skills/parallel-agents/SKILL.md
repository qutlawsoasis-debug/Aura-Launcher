# Параллельная работа через субагентов

Если у тебя нет возможности запускать субагентов, первой строкой ответа напиши об этом и работай последовательно.

## Когда запускать
- Задач 2 и больше, и они не зависят друг от друга.
- Большую задачу можно разрезать на части, которые трогают разные файлы.
- Нужно исследование (поиск по коду, чтение логов, диагностика) параллельно с правкой.

## Когда не запускать
- Задача одна и маленькая.
- Задача B использует результат задачи A. Такие делай по порядку.
- Две задачи правят один и тот же файл. Отдай их одному субагенту или сделай последовательно.

## Порядок
1. Раздели запрос на задачи. Для каждой определи список файлов, которые она тронет. Если списки пересекаются, объедини или упорядочь задачи.
2. Запусти по одному субагенту на независимую задачу, максимум 5 одновременно.
3. Каждому субагенту дай самодостаточное задание: что сделать, какие файлы можно менять, какие нельзя, какой результат должен быть виден, прочитать AGENTS.md и нужные скиллы. Он не видит твой контекст.
4. Субагент не коммитит, не собирает релиз и не трогает файлы вне своего списка.
5. Когда все закончили, сам проверь итог: общая сборка один раз, затем сценарий пользователя.
6. Если два результата конфликтуют, разреши конфликт сам, не перекладывай на пользователя.

## Отчёт
Пользователю одной-тремя строками: что теперь работает и как это увидеть. Без списка субагентов, файлов и метрик. Если какая-то задача не удалась, скажи об этом первой строкой.
