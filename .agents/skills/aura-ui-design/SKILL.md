# Дизайн Aura

Цель: интерфейс выглядит как работа живого продуктового дизайнера, а не как шаблон ИИ.
Лаунчер для друзей: сдержанно, плотно, читаемо. Опорные продукты: Modrinth App, Prism Launcher,
Lunar Client, официальный Minecraft Launcher; по эстетике Linear и Raycast.
Перед работой посмотри папку references/ рядом с этим файлом (скриншоты хороших и плохих примеров).

## Запреты (антишаблонный список)
- Плашки-пилюли с цветным фоном или обводкой вокруг обычного текста (версии, метки, бейджи).
  Версию писать обычным серым текстом.
- Карточка внутри карточки. Максимум один уровень контейнера; дальше отступы и тонкие линии.
- Свечение, неоновые тени, градиенты на тексте, стеклянный блюр повсюду.
- Текст-наполнитель, не несущий информации (слоганы, "Пиксельная развёртка • Слой брони",
  блоки "Советы"). Каждая надпись должна быть нужна пользователю.
- Несколько акцентных цветов. Тяжёлый шрифт (Black) для заголовков.
- Одинаковые кнопки без главного действия.
- Прозрачные пиксели скина, залитые чёрным.

## Токены (хранить только в UiTheme.xaml)
Фон окна #0F1115, поверхность #171A21, граница #252A33, текст #E8EAED, вторичный текст #9AA3B2,
акцент #19D3A7. Акцент только для кнопки ИГРАТЬ, активной вкладки и статуса успеха/ошибки.
Радиусы 6 и 10. Отступы 4/8/12/16/24/32. Один шрифт (Segoe UI Variable или встроенный Inter),
размеры 12/14/16/24, заголовки semibold. Весь текст >= 4.5:1 к фону.

## Состояния
У каждого интерактивного элемента есть normal / hover / pressed / disabled / focus.
Hover не снижает контраст текста: фон светлее на 6-8%, рамка чуть светлее.

## Скин
Превью: пиксель-арт, масштаб целым множителем, NearestNeighbor, прозрачность сохраняется.
Слои: голова (8,8,8,8)+шляпа (40,8,8,8), тело (20,20,8,12)+куртка (20,36,8,12), руки и ноги
с внешними слоями (для 64x32 внешних слоёв нет); slim-руки 3 px не растягивать.

## Процедура проверки (обязательна)
1. Запусти приложение в режиме снимков (--selftest-shots), получи PNG всех вкладок.
2. Открой снимки и опиши каждый словами: что на экране, что нечитаемо, что криво.
3. Сверь с references/ и с запретами выше. Перечисли минимум 3 места, которые всё ещё хуже
   эталона, и исправь их или честно оставь в отчёте.
4. Не пиши "выглядит хорошо": только факты со снимков.
В отчёте: что сделано, что не проверено, какие расхождения с эталоном остались.
